# nealxos

NixOS flake config. Most settings and system packages are shared across machines in
`common/`; each machine only carries what is genuinely machine-specific in `hosts/<host>/`.
Users are defined once under `user/`.

## Layout

| Path | Purpose |
| --- | --- |
| `flake.nix` | Inputs (nixpkgs, home-manager, vscode-server) and one `nixosConfigurations.<host>` entry per machine |
| `common/` | Shared across all hosts: system packages, locale, SSH, editor, nix settings |
| `hosts/<host>/hardware-configuration.nix` | Generated by `nixos-generate-config`; don't hand-edit |
| `hosts/<host>/configuration.nix` | Only machine-specific bits: bootloader, hostname, `system.stateVersion` |
| `user/<name>/default.nix` | System-level account (groups, description) |
| `user/<name>/home.nix` | Home Manager config: user packages and dotfiles |

Currently defined hosts: `vmware` (system name `nealxos`).

## Common operations

Run from the repo root. Flakes ignore untracked files, so `git add` new files before building.

```bash
# Apply config for the current machine and make it the boot default
sudo nixos-rebuild switch --flake .#<host>

# Apply only on next boot (safer for kernel/bootloader changes)
sudo nixos-rebuild boot --flake .#<host>

# Activate without adding a boot entry; reverts on reboot
sudo nixos-rebuild test --flake .#<host>

# Build without activating
nixos-rebuild build --flake .#<host>

# Build and deploy to another machine over SSH
nixos-rebuild switch --flake .#<host> --target-host <user>@<addr> --use-remote-sudo
```

If the flake output name matches the machine's hostname, `.#<host>` can be shortened to `.`.

### Adding a new host

```bash
sudo nixos-generate-config --show-hardware-config > hosts/<host>/hardware-configuration.nix
```

Then add a `configuration.nix` + `default.nix` next to it (copy an existing host as a
starting point) and register it in `flake.nix`, listing `./common` and `./user` in its
modules so it picks up the shared config.

### Updating

```bash
nix flake update              # bump all inputs
nix flake update nixpkgs      # bump a single input
```

`flake.lock` pins everything and is shared by all hosts, so commit it after updating.

### Adding packages

- Every machine (the default): `environment.systemPackages` in `common/default.nix`
- One machine only: `environment.systemPackages` in that host's `configuration.nix` — the
  lists merge, so this adds to the common set rather than replacing it
- Per user, with config attached: `home.packages` / `programs.*` in `user/<name>/home.nix`

Find package names with `nix search nixpkgs <term>`.

### Rollback and cleanup

```bash
sudo nixos-rebuild switch --rollback   # back to previous generation
nixos-rebuild list-generations         # what's available to boot into
sudo nix-collect-garbage -d            # delete old generations and unreferenced store paths
```

Older generations also appear in the bootloader menu at startup.

### Formatting / checking

```bash
nixfmt **/*.nix             # formatter used in this repo
nix flake check             # evaluate all outputs
```

## Notes

- `system.stateVersion` and `home.stateVersion` record the release a machine/home was first
  installed with. They are per-host and should not be bumped on upgrade.
- Passwords are not declared here; set them with `passwd` on each machine.
- `services.vscode-server.enable` patches the VS Code remote server so it runs on NixOS.
